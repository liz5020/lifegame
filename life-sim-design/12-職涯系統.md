# 十二、職涯系統(9/20新增)

> 本章與八、興趣系統、九、大學科系系統同等級,獨立成章但不新增回合預算,所有機制掛在二、2.5定義的22歲以後回合預算內運作。本章同時補上九、9.3已結案的「職涯伏筆觸發點」,見12.11。

## 12.1 規模與定位

- 【定案】涵蓋範圍:求職與面試、在職表現與升遷、轉職、失業與裁員、創業、職場人際、退休離開職場七塊
- 【定案】明確不涵蓋(沿用既有章節,本章不重複定義):薪資範圍表本身(3.4.3)、基本生活開銷(3.4.8)、資產與房貸(3.4.9)、房屋里程碑(7.5)、副業契機(8.7)、死亡機率的高風險職業加成(7.1.1)
- 【定案】不新增第二套「工作績效」數值。職場表現一律由既有數值合成(才識、自律、責任感、人脈),呼應9.9實作建議②「接上既有機制,不新增第二套學業公式」的同一精神
- 【定案,本章通則】職涯系統不產生「這一生成不成功」的判定。不升遷、不創業、一輩子同一份工作,都不得在幸福感上預設扣分(呼應六、6.4與三、3.8.4程式層禁令)。職涯事件只能透過「自我實現」「身心安穩」兩條管道的投入回饋影響幸福感,不得以career_status或job_level本身作為加減條件

## 12.2 回合節奏與判定頻率

- 【定案】兩種判定頻率分開處理,避免回合預算多寡影響判定密度(比照7.1.5「rollAnnualDeathCheck()每滿一個實際年齡才roll一次」的既有做法,與回合預算完全解耦):
  - 年度判定(每滿一個實際年齡判定一次):裁員風險、創業年度營運、退休候選
  - 段落型判定(佔用連續數個回合):求職期
- 【定案,測試參數】求職期佔3至5回合;畢業後第一次求職屬里程碑,放寬至5至6回合。這些回合從該年齡帶既有的回合預算內扣,不額外增加
- 【定案】求職期內部節奏比照二、2.2學期段落的混合式邏輯:不是每回合都重複「投履歷/不投」,中間穿插家人詢問、同儕比較、打工過渡、面試前準備等內容

## 12.3 職涯主狀態與薪資落點

- 【定案】職業分類完全沿用3.4.3的職業八大類,不另建職業表
- 【定案】薪資落點由三個因子決定,取代3.4.3原本只講「由才識決定落點」的單一因子(不是取代,是把3.4.3同一句裡「隨年資/職級成長」具體化):

| 因子 | 作用 |
|---|---|
| 才識(依類別可搭配邏輯或表達力) | 決定落點基準百分位 |
| job_level職級 | 每升一級,落點百分位往上推 |
| tenure_months年資 | 同一職級內的緩慢爬升,有天花板 |

  - 【定案,測試參數】落點百分位 ＝ clamp(才識÷100 × 0.5 ＋ 職級加成 ＋ 年資加成, 0, 1);職級加成新人0/熟手0.12/資深0.24/管理職0.36;年資加成 ＝ min(同職級年資年數 × 0.02, 0.08)
- 【定案】月薪 ＝ 類別下限 ＋(類別上限 − 下限)× 落點百分位,單位沿用3.4的遊戲幣單位
- 【定案】職級四級的語意依類別調整,不強求每類都有「管理職」:受雇白領為新人/熟手/資深/管理職;自由創作類為無名/接案穩定/有口碑/頭部;自營類改看12.8的經營規模,不套用本表
- 【定案】職業類別需帶is_high_risk旗標(工地、遠洋、特技、警消外勤等),供7.1.1死亡機率的高風險加成讀取,不在本章另算一套風險
- 【定案】薪資變動一律走3.4.7既有的月結算與收入變更機制,AI不得自行改寫薪資數字(見12.13責任邊界)

## 12.4 求職與面試

- 【定案】觸發時機三種:student_status轉為graduated或withdrawn後的下一回合(呼應9.8判斷是否出社會的既定依據,不看年齡)、失業後、玩家選擇轉職後
- 【定案】流程沿用9.5的共通四步驟模板:① AI鋪陳求職情境 → ② 程式產生可投遞的職業類別清單與各自錄取機率 → ③ 玩家決定投哪一類、要不要接受offer → ④ 兩層骰判定結果,細節層由AI發揮
- 【定案】可投遞清單不做鎖死,任何科系都能投任何類別(呼應9.3「科系只決定機率權重,不做獨佔鎖死」),科系只影響權重與錄取機率修正
- 【定案,測試參數】錄取機率 ＝ 基礎35% ＋ 各項修正,下限5%、上限90%:

| 修正項 | 幅度 |
|---|---|
| 才識 | (才識 − 50)× 0.4 個百分點 |
| 人脈 | (人脈 − 50)× 0.2 個百分點 |
| 成就傾向 | (成就傾向 − 50)× 0.3 個百分點(直接沿用3.7.3既有公式,不另設一套) |
| 科系對應(見9.2對照表) | 投遞類別與科系對應時 ＋10 個百分點 |
| 跨類別轉職 | −10 個百分點(見12.6) |
| 肄業(withdrawn) | −10 個百分點 |
| 延畢(delay_years > 0) | −5 個百分點 |
| 中高齡 | 50歲以上 −10、55歲以上 −20 個百分點 |

  - 【定案】保底規則:連續3次求職失敗後,第4次必定出現一個「不穩定/待業類」或「勞力/服務類」的保底offer,玩家仍可拒絕。理由是呼應六、6.1細節層正向配額與七、7.3.3「不可無止盡重複讓玩家陷入負面循環」的既有精神,避免求職期變成無限迴圈
- 【定案】面試失敗不是卡關或懲罰,直接進入另一條敘事分支繼續(呼應11.3既有定案文字裡就舉了「求職失敗→繼續重找工作」這個例子)
- 【定案】第一份正職對應4.3.1既有的first_job里程碑,維持客戶端結構化自動判斷,不改

## 12.5 在職表現與升遷

- 【定案】不另設績效數值。升遷候選由三條結構化訊號共同判定:年資達門檻、自律與責任感維持在門檻以上、期間無重大負面職涯事件
- 【定案,測試參數】年資門檻:新人→熟手2年、熟手→資深4年、資深→管理職6年;自律與責任感門檻為50分(呼應3.7.3以50分為中性基準的既有結構)
- 【定案】條件檢查採「持續達標」而非單次跌破,呼應3.7.2與9.5.3既有的持續投入精神
- 【定案,測試參數】升遷成功機率 ＝ 基礎40% ＋(成就傾向 − 50)× 0.3 個百分點,直接沿用3.7.3既有公式,本章不另設第二套
- 【定案】升遷成功後:job_level ＋1,薪資落點依12.3重算,同時套用3.7.3既有的健康扣分倍率,不另設代價
- 【定案】玩家可以拒絕升遷,記為skip_reason: chosen,依3.8.4推高自主感管道。拒絕升遷不扣幸福感,也不影響後續升遷資格
- 【定案】職級封頂後不再出現升遷候選,改為每隔一段時間出現「維持現狀/轉職/創業」的岔路點,避免中後段職涯只剩空轉的日常回合
- 【定案】升遷候選需有冷卻機制(比照9.5.1轉系冷卻與9.5.2雙主修4回合冷卻),冷卻回合數待校準

## 12.6 轉職

- 【定案】七、7.2已定案職涯不設終身鎖死,本節補的是判定規則,不變更該原則
- 【定案】觸發兩軌(呼應8.1興趣系統的被動/主動雙軌):
  - 主動:玩家自由輸入出現轉職意圖,或在12.5的岔路點主動選擇
  - 被動候選:升遷候選連續兩次未成立、或健康數值連續下降達門檻,由程式判定候選成立後由AI鋪陳情境
- 【定案】被動候選的判定訊號一律採可結構化觀察的數值,不使用幸福感(幸福感為隱藏數值,且依3.8.1只承擔敘事溫度與軌跡紀錄兩項用途,不進入判決迴路)
- 【定案】同類別轉職與跨類別轉職分開處理:
  - 同類別:tenure_months保留,job_level保留,薪資落點重骰但不折價
  - 跨類別:職業類別切換為新類別(呼應3.4.3「轉職即代表切換到新的職業類別區間」),job_level降一級(不低於新人),tenure_months歸零,錄取機率套12.4的跨類別 −10 個百分點
- 【定案】轉職成功判定沿用12.4的求職機率公式,不另設一套
- 【定案】轉職寫入人生履歷(4.2.2已定案轉職屬「有既有結構化訊號可直接判斷」的類型),仍受4.2.2每階段2次上限約束
- 【定案】轉職候選需冷卻,避免連續回合重複提案(比照9.5.1)

### 12.6.1 海外型轉職(9/20新增,承接9.3海外線伏筆)

- 【定案】9.3「海外線」伏筆不另開獨立章節,併入本節,列為跨類別轉職的一種特殊型態:留學、外派、移居都視為「轉職」的子情境,沿用12.6既有的跨類別規則(job_level降一級、tenure_months歸零、錄取機率套跨類別−10個百分點),不另建一套機制
- 【定案】海外型轉職額外疊加一項一次性事件成本(比照12.8創業啟動資金的具體金額判斷精神):留學/外派/移居前須通過現金門檻檢查(具體金額待校準),現金不足時該選項不成立,客戶端直接擋下,不扣款、不切換狀態
- 【定案】海外型轉職成功後,原有的NPC關係(4.1)不強制切斷,依4.1既有的12回合無互動降級規則自然淡出;`cohabiting`同住標記(4.1.2)則依既有規則在搬離時解除
- 【定案】海外型轉職是否影響死亡機率(7.1.5)或健康,不另設專屬修正,沿用一般轉職與一般生活開銷規則

## 12.7 失業與裁員

- 【定案】裁員由程式年度判定,不由AI依敘事情境自行宣判(呼應9.9「AI不可自己宣判已休學/肄業」的同一責任邊界)
- 【定案,測試參數】年度裁員機率依職業類別分流,再乘年資修正:

| 職業類別 | 年度裁員機率 |
|---|---|
| 軍公教/警消類 | 0.5% |
| 受雇專業/白領類 | 2% |
| 長期不在身邊類 | 3% |
| 政治人物子女(自身從政) | 3%(另含選舉落敗性質的事件) |
| 勞力/服務類 | 4% |
| 不穩定/待業類 | 12% |
| 自由/創作類 | 不適用,改以接案空窗呈現(收入波動,非狀態轉換) |
| 自營/家庭事業類 | 不適用,改由12.8年度營運判定承接 |

  - 【定案,測試參數】年資修正:年資每滿3年 ×0.9,累乘下限0.5倍
- 【定案】裁員敘事不得寫成「因為玩家表現差」的單一歸因,須保留公司結構調整、產業變動、部門裁撤等非玩家因素(呼應六、6.1「不讓負面事件淪為無法預期的懲罰」的精神,與7.1.2前兆機制同源)
- 【定案】裁員前需有前兆(同事陸續離職、專案被砍、主管態度變化等),比照7.1.2前兆機制的設計精神,不毫無徵兆直接觸發
- 【定案】失業狀態:career_status = unemployed,月收入歸零,但3.4.8基本生活開銷依既有定案持續存在,財務壓力由既有機制自然產生,不另設懲罰
- 【定案】失業後自動進入12.4求職段落,保底規則照舊套用
- 【定案】失業期間不進行裁員判定,也不因失業改變7.1.5死亡機率(40歲門檻與公式維持不變)

## 12.8 創業

本節填補目前文件多處引用卻從未定義的缺口:3.4「創業啟動資金門檻」、3.4.3「自營/家庭事業類波動大,創業成敗直接影響」、3.7.3「創業/升遷機率」、4.3.1「第一次創業」里程碑、7.2「創業失敗重來」、9.3創業線伏筆權重。

### 12.8.1 啟動門檻

- 【定案,9/20取代原雙條件草案】啟動門檻改為單一條件:**現金 ≥ 啟動資金**,採具體金額判斷,比照7.5.3買房頭期款的既定做法。現金不足時創業不成立,客戶端直接擋下,不扣款、不建立事業、不讓現金變負值
- 【定案】不另設財務健康度資格層——原草案曾比照3.4「財務健康度供創業啟動資金門檻使用」的舊說法設計雙條件(資格層+扣款層),但拍板結果是單一現金門檻更直接,3.4該處舊說法已同步修正(見03-核心數值系統.md 3.4開頭補充定案)
- 【定案,測試參數】啟動資金 ＝ 該類別月薪中位數 × 12(遊戲幣單位)
- 【定案】創業來源三條:9.3創業線伏筆觸發(見12.11)、8.7副業轉正(side_business狀態持續一定回合後升級為候選)、玩家自由輸入

### 12.8.2 成敗判定

- 【定案】創業不是一次骰定生死,改採年度營運判定,呼應7.1.5「不設固定值、改逐年判定」的同一設計方向
- 【定案,測試參數】年度營運成功率 ＝ 基礎45% ＋(成就傾向 − 50)× 0.3 ＋ 才識修正 ＋ 人脈修正 ＋ 相關興趣投入度修正,上限＋5個百分點
- 【定案】興趣投入度只能作為有上限的修正項,不得直接當成功率使用,這是8.4已定案的限制,本節不得繞過
- 【定案】判定結果三態:成長(薪資落點上移、經營規模升級)/持平/虧損(依規模扣除現金)
- 【定案,測試參數】連續2年虧損成立收攤候選,冷卻4回合(比照9.5.2的冷卻設計);玩家選項為收攤止損/再撐一年/增資(增資須通過12.8.1的現金門檻檢查)
- 【定案】收攤後回到12.4求職段落,不卡死人生(呼應7.2),也不得在敘事上寫成人格判決或蓋棺定論(呼應7.1.4改版後的整體精神)
- 【定案】健康代價沿用3.7.3成就傾向的健康扣分倍率,不另設

### 12.8.3 里程碑歸屬

- 【定案,9/20確認】「第一次創業」改列為客戶端結構化自動判斷,比照9/16「第一次戀愛」從AI回報改列客戶端判斷的前例——本章定義`business_status`後,`business_status`轉為「經營中」即為明確的結構化訊號,不再需要AI回報。已同步修改4.3.1里程碑清單(見04-角色卡與人生歷史系統.md)

## 12.9 職場人際

- 【定案】不另建職場專屬關係系統,完全沿用4.1既有的NPC角色卡架構與同一套0-100關係值,理由同4.4戀愛系統的既有判斷(單一正本、不重複建置、不增加AI context成本)
- 【定案】4.1「關係類別」欄位新增四種值:同事/主管/下屬/客戶或合作對象
- 【定案】人脈成長沿用3.5.2,並套用3.7.3既有的責任感倍率與團隊值倍率,本章不另設職場專屬成長公式
- 【定案】職場人際的機制出口三條:12.4/12.6的人脈修正、12.5升遷候選的訊號之一、12.8創業合夥的可行性(團隊值偏單打獨鬥的角色,合夥類選項出現權重降低,但不鎖死)
- 【定案】換工作後舊同事沿用4.1既有的「12回合無互動自動降級為背景NPC」規則自然淡出,不另設離職清空機制;日後可依8.6的喚醒精神在敘事上重新出現
- 【定案,本版明確不做】辦公室政治小遊戲、忠誠度數值、派系系統。留待未來需要時再疊加,比照4.4戀愛系統先做簡單版的處理方式

## 12.10 退休與職涯結束(9/20整併,吸收十三、13.4的健康衰退章草案內容)

**取代關係**(說明用,非規則):本節原內容與十三、13.4「退休」是兩個各自獨立進行的討論分別產生的退休機制,9/20發現後由使用者拍板整併為一份,以本節為準;13.4改寫為只保留健康/疾病連動的補充,不再重複定義退休本身的觸發、選項、財務規則。

- 【定案】退休不是強制年齡事件,到年齡出現候選,玩家可選擇繼續工作(呼應6.4「永遠可以跳過」)
- 【定案,測試參數】60歲起出現退休候選,65歲起每年出現一次
- 【定案,9/20整併,取代原「玩家可選擇繼續工作」的簡化敘述】候選觸發時提供六個選項,不是單純二選一:
  1. 準時退休
  2. 延後退休(繼續工作,最晚至70歲)
  3. 提早退休(55歲起開放,需財務健康度門檻)
  4. 半退休(兼職、接案、志工,收入下降但保留職涯認同,`career_status`轉為半退休專屬狀態,不等同完全退休)
  5. 不退休(自營、創作、農業等職業類別適用,呼應12.3職業類別本身職級語意的彈性)
  6. 自訂輸入
- 【定案,9/20新增,來自十三、健康衰退與老年階段章】被迫退休分支:健康低於閾值、或處於重大疾病治療期(見十三、13.3.4)時,觸發非玩家選擇的離開職場事件,不經過上述候選六選項。後續仍須提供選項(復出、半退休、專心療養),不讓玩家停在無事可做的狀態
- 【定案】退休後月收入轉為退休金,依職業類別分流(軍公教/警消類比例最高,不穩定/待業類與自由/創作類最低或無),3.4.8基本生活開銷依既有定案持續存在
- 【定案,9/20整併,取代原本沒有具體公式的「依職業類別分流」敘述】退休金採簡化模型,不做勞保/勞退/國民年金等真實制度分軌:每月固定收入＝退休前月薪×替代率,替代率依職業類別在40%到60%區間內分流(軍公教/警消類取上緣、不穩定/待業類與自由/創作類取下緣或無)【測試參數,待驗證】,並依年資微調,掛三、3.4.7週期性收支結算——直接沿用既有的週期性收支結算機制,不另外做年金制度的擬真細節
- 【定案,9/20新增】正職薪資於退休當月的下一個完整月份起歸零,沿用3.4.7既有的「下一個完整月份才計入」規則,與退休金收入銜接不留空窗
- 【定案】退休不扣幸福感。自我實現管道改由興趣投入度(8.3)與家庭關係承接,這是3.8.2既有五條管道取前三高加權的機制自然結果,不需另設補償規則。代碼中不得出現「若已退休則幸福感−x」這類寫法(呼應3.8.4程式層禁令)
- 【定案】自營/家庭事業類的退休可觸發「交棒」分支,接七、7.4世代傳承的既有機制,並與9.3「接手家業」伏筆線在下一世銜接

## 12.13 AI/程式責任邊界(開發實作參考,比照9.9)

| 項目 | 程式負責 | AI可以做 | AI不可以做 |
|---|---|---|---|
| 求職/面試 | 可投遞清單、錄取機率、成敗 | 描寫面試過程、等待、結果細節 | 自行決定「這個人應該會被錄取」 |

## 12.14 與十一、明牌檢定白名單的關係

## 12.15 明確待測試項目(交付QA測試部)

1. 錄取機率公式各項修正幅度:是否出現「才識高就必定錄取」或「肄業幾乎找不到工作」的失衡
2. 保底offer的3次門檻:過早會讓求職失去張力,過晚會讓玩家卡在迴圈
3. 各類別年度裁員機率:跑完整人生模擬,觀察一生中被裁員次數的分布是否合理
4. 創業啟動門檻(單一現金門檻):實測有多少比例的角色一生中摸得到創業,過低代表這條線形同虛設
5. 年度營運判定三態比例與連續虧損2年的收攤門檻
6. 升遷年資門檻與職級封頂年齡:確認多數角色不會在40歲前就封頂,導致後半生只剩空轉回合
7. 12.11五個伏筆觸發點的實際觸發頻率,接9.7測試項目4的第二階段校準
8. 12.6.1海外型轉職的一次性現金門檻具體金額,待校準
