# 《人生草稿｜QA 測試手冊 v1》

> 版本：v1\
> 對應設計文件：《人生草稿------完整設計文件彙整》\
> 測試目的：確認《人生草稿》的「程式決定事實、AI負責敘事」架構，在數值、時間、事件、NPC、財務與長期人生路徑上能穩定運作。\
> 測試原則：**不是只測「能不能玩」，而是刻意把遊戲玩壞。**

------------------------------------------------------------------------

# 一、測試總目標

QA 不只是找程式 bug，也要確認三件事：

1.  **規則真的有被執行**
    -   數值變化符合設計。
    -   時間推進正確。
    -   財務結算正確。
    -   事件不重複或錯誤跳轉。
    -   人格光譜確實會影響行為與機率。
2.  **AI 沒有越權**
    -   AI不能自行決定日期、金額、機率、NPC設定或重大結果。
    -   AI不能寫出與實際 World State 矛盾的內容。
3.  **玩家選擇真的會留下痕跡**
    -   同一個事件做不同選擇，長期人生應該逐漸分流。
    -   不是每條路最後都收斂成同一個人生。

------------------------------------------------------------------------

# 二、測試分級

  等級      定義                                              處理
  --------- ------------------------------------------------- --------------
  P0 致命   無法繼續遊戲、資料毀損、核心規則完全失效          立即修正
  P1 嚴重   核心數值/時間/財務/事件結果錯誤，會破壞人生模擬   優先修正
  P2 中等   特定分支錯誤、NPC記憶遺失、敘事與狀態不一致       排入近期修正
  P3 輕微   用詞、排版、偶發不自然敘事                        後續修正

# 四、測試 A：四條人格機制單獨驗證

這是第一優先測試。

每次只改一個人格數值，其他條件完全相同。

------------------------------------------------------------------------

## A-1 審慎測試

### 目的

確認：

> 審慎高 → 細節層結果比較集中\
> 審慎低 → 細節層結果波動較大

設計中的基準公式：

``` text
細節層隨機範圍
= 基準隨機範圍 × [1 − (審慎−50) × 1%]

限制：
0.5倍～1.5倍
```

### 測試角色

  角色     審慎
  ------ ------
  A          20
  B          50
  C          80

其他數值完全相同。

### 測試方法

讓三個角色各執行相同重大決策至少20次。

例如：

-   創業
-   財務投資
-   轉系
-   重大感情決策

### 預期

審慎20： - 結果散布較大。 - 可以大好，也可以大壞。

審慎50： - 基準波動。

審慎80： - 結果明顯集中。 -
不代表比較容易成功，只代表比較不容易出現極端結果。

### Bug 判定

-   審慎高低完全沒有差異 → P1
-   審慎高反而永遠成功 → P1
-   審慎低只會得到壞結果 → P1
-   波動差異過度誇張 → P2

------------------------------------------------------------------------

# 五、測試 B：成就傾向

設計公式：

``` text
成功機率
= 基礎機率 + (成就傾向−50) × 0.3 個百分點
```

因此：

-   0 → -15%
-   50 → 0%
-   100 → +15%

### 測試角色

  角色     成就傾向
  ------ ----------
  A              20
  B              50
  C              80

### 測試事件

固定測：

-   升遷
-   創業
-   爭取更高職位
-   高風險職涯機會

### 方法

每個角色至少測100次。

如果正式系統還沒有大量自動測試能力，可以先用Debug模式反覆執行同一判定。

### 預期

在大量樣本下：

> 高成就傾向角色的成功率應高於中性角色；中性角色應高於低成就傾向角色。

不是要求20次一定符合理論百分比，而是看大量樣本的趨勢。

### 額外測試：健康代價

設計中的健康成本：

``` text
健康扣分倍率
= 1 + (成就傾向−50) × 1%
```

確認：

-   高成就 → 拼事業時健康成本較高。
-   低成就 → 健康成本較低。
-   但不能變成「高成就一定生病」。

------------------------------------------------------------------------

# 六、測試 C：責任感

設計：

``` text
正向人脈增益倍率
= 1 + (責任感−50) × 1%

負向人脈損失倍率
= 1 + (50−責任感) × 1%

倍率限制：0.5～1.5
```

### 測試角色

  角色     責任感
  ------ --------
  A            20
  B            50
  C            80

### 測試兩種情境

#### 正向

例如：

> 答應朋友幫忙 → 有做到。

觀察人脈增加量。

#### 負向

例如：

> 答應朋友事情 → 沒做到。

觀察人脈扣除量。

### 預期

高責任感：

-   做到承諾 → 人脈增加較多。
-   發生負面事件 → 扣分較少。

低責任感：

-   正向累積較慢。
-   負面事件扣分較重。

### Bug

如果責任感只影響AI文字、完全不影響數值 → P1。

------------------------------------------------------------------------

# 七、測試 D：團隊 vs 單打獨鬥

設計：

``` text
人脈成長倍率
= 1 + (團隊−50) × 1%

才識/邏輯成長倍率
= 1 + (50−團隊) × 1%
```

### 測試角色

  角色     團隊傾向
  ------ ----------
  A              20
  B              50
  C              80

### 測試事件

固定比較：

1.  小組報告
2.  社團活動
3.  個人研究
4.  解謎/策略
5.  專業技能投入

### 預期

團隊80：

-   團體活動的人脈效率較高。
-   個人鑽研效率相對低。

單打20：

-   個人鑽研的才識/邏輯效率較高。
-   人脈累積相對慢。

### 核心原則

**不能測成「團隊型永遠比較強」。**

應該是兩種人生路徑各自有優勢。

------------------------------------------------------------------------

# 八、測試 E：時間軸

時間是《人生草稿》最容易產生隱性 Bug 的地方之一。

原設計要求：

> 日期由程式計算，AI只讀取結果。

## E-1 單回合時間

測：

-   幾天
-   幾週
-   一個月
-   半年
-   一年
-   1～2年

確認：

-   日期正確。
-   年齡正確。
-   學期正確。
-   新的一天/新的一週判定正確。

## E-2 跨年份

例如：

``` text
2029/12/20 → 2030/01/10
```

檢查：

-   年份是否正確。
-   年齡是否錯跳。
-   財務是否正確結算。

## E-3 長時間跳躍

例如：

``` text
25歲 → 28歲
```

檢查AI是否：

-   直接跳到重大事件。
-   忘記中間人生。
-   把3年寫成幾天。
-   NPC關係突然無理由改變。

若有重大里程碑且時間跳躍明顯，應先有過渡敘事。設計文件已明定此規則。

# 九、測試 F：財務系統

財務必須獨立測。

設計採：

> 月份邊界整月淨額法。

## F-1 不跨月份

``` text
3/10 → 3/20
```

預期：

> 不結算週期性收入/支出。

## F-2 跨一個月份

``` text
3/15 → 4/2
```

預期：

> 結算一個月份邊界。

## F-3 跨多個月份

``` text
3/15 → 5/2
```

預期：

> 分別結算跨過的月份，而不是把整段時間混成一次。

## F-4 跨很多月份

``` text
2029/03 → 2030/03
```

預期：

> 不需要逐月把所有資訊塞進敘事，而應使用區間總結格式。

# 十、測試 G：薪水、租金、房貸切換

這一組非常重要。

### 情境 1：中途入職

``` text
3/15 開始工作
月薪 NT$40,000
```

測：

> 3月到底有沒有拿到完整月薪？

目前設計採「查詢該月生效中的數字直接套用、不按日比例」規則。

因此這裡要特別記錄測試結果是否符合產品目前定案。

### 情境 2：中途搬家

``` text
3/20 搬家
新租金 NT$18,000
```

檢查：

-   舊租金是否錯誤延續。
-   新租金是否錯誤追溯。
-   是否出現兩份租金。

### 情境 3：買房

買房的詳細測試項目（頭期款、房貸固定支出、財務惡化逆向選擇等）已併入「十七、測試N：房屋系統」統一處理，避免同樣的檢查項目分散在兩個章節裡各寫一次。這裡只留一句提醒：買房後房貸要能正確併入週期性收支結算，跟情境1、2用的是同一套機制，測完情境1、2後可以直接接著測十七。

# 十一、測試 H：零用錢

這是目前特別需要測的設計點。

### 問題

如果零用錢是每月收入，而玩家沒有「花掉」它，可能會變成：

> 每個月一直累積錢，但玩家根本沒有做任何消費行為。

### 測試角色

建立三個學生：

#### A：極度節省

幾乎不消費。

#### B：一般

有正常生活消費。

#### C：極度消費

大量購買物品、娛樂。

### 檢查

三個角色到了18～22歲：

-   財富是否合理分化？
-   「完全不花錢」是否變成最優策略？
-   玩家是否需要每回合手動花錢才能維持生活？
-   零用錢與一次性消費是否分得清楚？

### Bug 指標

如果最優策略變成：

> 「什麼都不做，只收零用錢」

就需要重新調整經濟模型。

# 十二、測試 I：考試系統

目前設計已將「智慧」改成長期效率，而不是每次考試直接再次加總；考試主要看目前才識與本次備考努力。

### I-1 智慧差異

建立：

-   智慧20
-   智慧50
-   智慧80

其他條件相同。

讓三者讀相同次數。

預期：

> 高智慧長期累積才識較快。

### I-2 讀書努力差異

同一角色：

-   讀0次
-   讀2次
-   讀5次

預期：

> 讀書越多，考試落點通常越高，但仍保留細節層意外。

### I-3 防止雙重計算

檢查：

> 智慧是否已經透過才識累積反映後，又在考試結果中被再次直接加一次？

若有，就是核心公式 Bug。

# 十四、測試 K：NPC 記憶

這是長期遊戲品質的核心。

建立一個NPC：

> 林○○

然後讓玩家：

1.  第一次認識
2.  一起做報告
3.  幫助對方一次
4.  發生一次衝突
5.  一年後再次見面

### 預期

一年後AI仍應知道：

-   他是誰。
-   怎麼認識。
-   過去發生過什麼。
-   關係大致如何。
-   某些重要共同記憶。

### Bug

如果一年後：

> 「你第一次認識林○○。」

但實際上已認識一年。

→ P1/P2。

# 十六、測試 M：自由輸入

自由輸入不是只有「模型能不能理解」。

還要測：

1.  輸入長度。
2.  是否被截斷。
3.  是否被錯誤解析。
4.  是否影響正確數值。
5.  是否能產生合理事件。

### 建議測試長度

``` text
10字
30字
50字
100字
200字
300字
500字
1000字
```

### 特別測試

輸入：

> 「我今天什麼都不想做，就坐在便利商店外面發呆兩個小時。」

檢查系統是否能理解：

-   玩家沒有選擇標準選項。
-   行為本身成立。
-   時間有推進。
-   可能影響幸福感/健康/人格，但不能亂加數值。

### UI 測試

如果實際輸入框限制很短：

> 不要讓文字「靜默截斷」。

應顯示明確提示，例如：

> 已輸入 96 / 300 字。

# 十七、測試 N：房屋系統

> 本節也涵蓋原本「十、測試G」情境3的買房檢查項目（頭期款、房貸固定支出、後續扣款、賣房/轉租逆向選擇），兩處內容重複，統一寫在這裡。

測四條路：

1.  一直住家裡。
2.  一直租屋。
3.  存錢買房。
4.  買房後財務惡化。

### 重點

檢查：

-   租金是否正確。
-   頭期款是否正確。
-   房貸是否持續扣款。
-   買房是否真的改善居住狀態。
-   財務危機時是否有逆向選擇。
-   不買房是否被幸福感暗中懲罰。

設計文件明確要求租屋、買房、住家裡並列，不應把買房當成唯一正確人生。

# 十八、測試 O：生育/不生育

至少建立：

### A：生育

### B：不生育

### C：單身但想領養

### D：嘗試後進入不孕症路線

檢查：

# 十九、測試 P：死亡與意外

### P-1 年齡門檻

15～18歲：

> 不應觸發意外死亡。

19歲開始：

> 意外死亡機制啟動。

### P-2 健康因素

比較：

-   健康90
-   健康50
-   健康20

預期：

> 健康越低，風險提高。

### P-3 高風險職業

比較：

-   一般白領
-   高風險工作

確認：

> 職業風險是額外因子，而不是直接取代健康因素。

### P-4 前兆

若即將發生重大意外：

> 前面應存在某種微小前兆。

不能突然：

> 「你走在路上，突然死了。」

設計文件已明定意外前需要有微小前兆。

# 二十、測試 Q：人格光譜長期累積

不要只測單一事件。

建立：

> 「長期審慎型」

連續20～30個選擇都偏向：

> 觀望、比較、先確認。

另一個角色：

> 「長期衝動型」

連續20～30個選擇都偏向：

> 當下決定、直接行動。

### 檢查

多年後：

-   兩人的人格行為是否真的不同？
-   敘事語氣是否有差異？
-   重大決策的細節波動是否不同？
-   是否仍然可以偶爾做出違反底色的選擇？

### 重要

人格不是宿命。

因此要測：

> 長期審慎型角色突然做一次衝動選擇。

應該：

-   可以做到。
-   不會立刻變成人格完全相反的人。
-   可以觸發「破格時刻」。

設計文件要求性格破格時刻具有明顯的敘事份量，且至少部分情況能與父母等角色的關係史連動。

# 二十三、完整人生測試時要特別觀察的10件事

每跑完一局，回答：

### 1. 有沒有「唯一正確玩法」？

例如：

> 一定要讀書 → 找好工作 → 結婚 → 買房。

如果這條路明顯碾壓其他路線，需要重新檢查。

### 2. 不做事是不是反而最划算？

例如：

> 不打工、不讀書、不交朋友，只拿固定資源。

如果長期最有利，就是經濟模型問題。

### 3. 人脈是否膨脹太快？

如果20歲左右就長期接近100，需要調整。

### 4. 財富是否爆炸？

例如：

> 25歲普通工作，30歲突然累積數千萬。

需要檢查收入/支出/跳年結算。

### 5. 健康是否太容易恢復？

如果連續熬夜、超時工作都沒有長期後果，健康系統失效。

### 6. 人格是否真的有用？

如果不同人格最後所有結果幾乎一樣：

> 人格系統只是裝飾。

### 7. NPC是否會消失？

如果重要NPC過幾年完全沒有記憶：

> NPC系統失效。

### 8. 玩家選擇是否留下長期後果？

如果不同選擇5年後完全一樣：

> 選擇系統失效。

### 9. 負面事件是否過多？

設計精神允許人生沉重，但不能讓玩家感覺：

> 「怎麼選都沒用。」

設計文件也將負面事件後的流失/退出集中情況列為重要監控指標。

### 10. AI有沒有開始「自己編遊戲規則」？

這是最高優先級之一。

# 二十四、分支持續性測試

這是確認「人生真的被玩家玩出來」的重要測試。

## 方法

在同一個存檔點建立兩條分支。

例如：

### Branch A

> 大學加入大型社團。

### Branch B

> 完全不參加社團。

然後各自跑5～10年。

比較：

-   人脈
-   NPC數量
-   工作機會
-   感情
-   職涯
-   幸福感
-   事件池
-   可用選項

### 預期

兩條人生應該逐漸分開。

不是：

> 22歲加入社團\
> ↓\
> 23歲兩人又拿到完全相同的人生。

# 二十五、極端角色壓力測試

建立幾個「故意不合理」角色。

## 角色A：全100

所有可設定數值：

> 100

檢查：

-   是否直接突破遊戲上限。
-   是否每件事都成功。
-   是否財富/人脈/才識爆炸。

## 角色B：全0

所有可設定數值：

> 0

檢查：

-   是否直接無法遊玩。
-   是否所有事件都失敗。
-   是否還存在正向意外。

## 角色C：矛盾角色

例如：

``` text
才識 90
人脈 10
健康 20
成就 100
審慎 0
責任感 100
團隊 0
```

目的：

> 測試系統能否處理互相衝突的角色特質。

# 二十六、AI敘事品質測試

數值正確後，再測文字。

每回合檢查：

### 時間

-   是否符合目前時間。
-   是否知道現在人生階段。

### 人物

-   NPC名字是否一致。
-   性別是否一致。
-   身份是否一致。

### 數值

-   不寫出錯誤金額。
-   不暗示錯誤結果。

### 語氣

-   是否符合依附風格。
-   是否符合角色年齡。
-   是否符合角色背景。

### 文體

設計要求：

-   約250～350字。
-   2～3小段。
-   句子長短有不對稱。
-   對話自然。
-   避免把人物心理直接全部說破。
-   重要情緒可以留下未收斂空間。

# 三十一、QA 最重要的判斷原則

測試時不要只問：

> 「這回合看起來自然嗎？」

要問：

> **「如果我把這個角色的人生重跑100次，這套規則是否仍然合理？」**

也不要只問：

> 「AI寫得好不好？」

要問：

> **「AI寫得很好時，有沒有可能把錯誤的事實寫得非常像真的？」**

《人生草稿》的核心不是單回合小說，而是：

``` text
玩家選擇
↓
程式改變 World State
↓
數值/人格/關係/旗標留下痕跡
↓
下一個事件池受到影響
↓
AI根據已確定事實敘事
↓
玩家再次選擇
↓
人生逐漸分叉
```

因此 QA 最終要驗證的不是「每個事件好不好玩」，而是：

> **這些事件串起來之後，真的像是一個人的人生，而不是一串彼此獨立的AI短篇小說。**

# 三十三、v1 結論

第一階段不要急著增加大量事件。
