## 你要特別標出的幾件事

### 1. 行動點
| | 位置 | 說明 |
|---|---|---|
| **檢查** | 步驟④（前端 9298），再加 Worker 端一次（步驟⑨） | 前端先看 `totalAP`，不夠就跳彈窗、不往下走。Worker 端：雲端開啟查 KV 紀錄，帳號人生查錢包，不夠回 402。**雲端暫停且非帳號人生時，Worker 完全不查點數，只靠前端本機檢查。** |
| **扣** | 步驟⑤（前端 9303）先扣；Worker 端在呼叫 Anthropic 前預扣 | 前端是呼叫 AI **之前**就扣了。Worker 的錢包或 KV 路徑也是先扣再呼叫。 |
| **退** | 失敗路徑（9467）`refundAP`，Worker 在回應不可用時也退 | 整個回合最後仍失敗才退。成功但內容品質不合格被重新產生，不會多扣（同一個 turn_nonce）。 |

開場那一回合（`prologue`）花費是 0。另有「測試用不扣點」開關，只有登記過的測試金鑰才生效。

### 2. AI 太慢或沒回
- **前端沒有逾時機制**：`callAI` 裡的 `fetch` 沒有 `AbortController`，也沒有逾時計時器。目前沒有處理。
- Worker 呼叫 Anthropic 的 `fetch` 也沒有自己設逾時。
- 太慢時的實際行為：畫面一直停在「撰稿人書寫中」，輸入、送出都被擋住（`turnsInFlight`），直到瀏覽器或 Cloudflare 自己斷線，才會走到失敗流程。
- 瀏覽器預設等多久、Cloudflare Worker 的實際時間限制是多少，**不確定**（程式裡沒寫，是平台行為）。
- 斷線、完全沒回：`fetch` 丟例外 → 重試 1 次 → 還是失敗 → 還原快照、退點、顯示「撰稿人一時沒接上線，這一回合還沒扣點」，附「再試一次」按鈕。

### 3. AI 回的格式不對或空白
- **空白回應**：丟錯 → 重試 1 次 → 仍失敗就走失敗路徑。
- **不是 JSON、沒有 `submit_turn_result`、有偽 XML 標籤、必要欄位空、非結局卻沒有選項**：都丟錯 → 同上流程。Worker 端也用相同標準判斷「不可用」，這種回應**不扣點**。
- **缺少次要欄位**：前端用預設值補上（`fillOmittedTurnFields`），不算失敗。
- **正文品質不好**（引號沒關、句子沒寫完、有大括號）：自動重新產生最多 2 次，之後仍不合格就保留最後一次、記進待確認清單，玩家照常看到。
- **場景日期違規**：重新產生 1 次，仍違規就照常顯示並記錄。
- 失敗時玩家只看到中性的一句話，錯誤細節只寫進 console，不外洩。
- 重試時要不要等一下再打：**目前沒有處理**，是立刻重打。

### 4. 玩家輸入奇怪內容
- **有擋的**：空白（直接忽略，沒有提示）、超過 200 字（紅字提示）。Worker 端另有硬上限 300 字，payload 總長上限 40000 字。
- **目前沒有處理的**：
  - 特殊符號、亂碼、純表情符號。
  - 想叫 AI 忽略規則的提示詞注入。搜過 `index.html` 和 `worker/prompt.js`，沒找到任何對玩家輸入的過濾或關鍵字檢查。
  - 不合理或不可能的行動，這部分全部交給 AI 的 system prompt 自己處理。
  - 輸入框內容在按送出時就清空了。回合失敗後輸入框不會自動還原，只有「再試一次」按鈕會用同一個行動重送。例外是每日花費上限暫停時，會把文字放回輸入框（`restoreCustomDraft`）。
- AI 回傳的選項文字會再經 `sanitizeChoiceNames` 處理。這只處理 AI 的輸出，不處理玩家輸入。

### 5. 本機存檔與雲端存檔
| | 在哪一步 | 失敗會怎樣 |
|---|---|---|
| **本機存檔** | 步驟⑮，`saveGame()` 寫 `localStorage`。每回合都存，失敗的回合也會存（含錯誤訊息那則日記） | 寫入失敗（例如空間滿）只在雲端暫停期間提示一次「存檔失敗」（`notifyLocalSaveFailed`），遊戲繼續。**不會阻止下一回合，也沒有備援。** 提示後同一段失敗期間不再重複提示。 |
| **雲端存檔（目前設定，雲端暫停）** | 步驟⑮，`autoSaveDue()` 判斷：真實 API、同意過、回合有推進、距上次成功 ≥10 分鐘。人生結束時再存一次。沒綁信箱也一樣 | 失敗不打擾玩家，只把頂部狀態列改成「雲端存檔失敗，稍後重試」，等 1 分鐘後的下一次存檔再試。本機那份不受影響。 |
| **雲端存檔（雲端開啟時）** | 步驟⑮，每回合 `cloudSyncOnce()` 都存 | 失敗時顯示「☁ 未同步」標籤，同一段失敗期間只跳一次提示，下回合再自動重試。 |
| **示範模式** | 不自動存雲端 | — |

兩種情況下，雲端存檔都在本機存完**之後**才做，雲端失敗不影響這回合結果。

## 不確定的地方

1. **失敗回合的還原範圍**：失敗時 `applySnapshot()` 還原的是快照裡的欄位。快照包含哪些欄位只看了前段（`snapshotForUndo` 9195~），沒逐一確認全部。步驟⑤中程式直接改動、但可能不在快照裡的東西（例如 `state.seekTarget` 被清掉、NPC 背景事件擲骰結果），失敗還原後會不會一併回復，**不確定**。
2. **帳號錢包的失敗退點**：前端在失敗時以伺服器最後回報的餘額為準（9468~9472）。若是網路根本沒連上、連伺服器回報都沒收到，前端的本機退點與伺服器端狀態是否一致，**不確定**。
3. **雲端暫停＋非帳號人生**：Worker 不查也不記點數，點數完全存在玩家瀏覽器。清除瀏覽器資料或改 localStorage 就能改點數，程式裡**目前沒有處理**（設計文件 10.8 寫的暫時狀態，這裡只確認程式現況）。
4. **「再試一次」按鈕**：會重新扣點、重新產生新的 turn_nonce，不是沿用失敗那次的 nonce。這點是從 `takeTurn` 開頭每次都重跑所推斷，沒有實際跑過。
